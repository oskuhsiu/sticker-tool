# 套用背景功能：去背邊緣殘色實測與建議

> 實測日期：2026-06-12。背景：工具一直在做「去背」，但多數用戶其實想要「有背景」。
> 規劃讓用戶套用背景前，先驗證一個疑慮——去背留下的淡色邊緣，疊上背景後會不會很明顯？

## TL;DR

- **會有殘色，但沒有想像中嚴重**；淺色背景幾乎看不見，深色／飽和背景在放大下可見約 1–2px 淡色暈邊，縮回貼圖實際顯示尺寸後相當不顯眼。
- **開白描邊後問題直接消失**——半透明邊緣混到的是墊在下面的描邊層，不是新背景。CLI 與 web 都已有描邊功能。
- 真正需要補強的只有「無描邊 + 深色/飽和背景 + 照片來源」這個組合：建議疊背景前做 1px alpha choke。

## 實驗方法

- 素材：`eval/fixtures/char_drink_bluebg.png`（藍底角色組圖，AI 產生、背景乾淨）
- 流程：跑工具自身的 `removeBackgroundLocal`（@imgly/background-removal-node）→ 疊到白／深灰 (40,40,48)／飽和黃 (250,200,60)／飽和綠 (80,180,90) 四種背景 → 另做一組「白描邊 8px 再疊背景」對照 → 邊緣局部 4x 放大
- 測試腳本：`tmp/fringe-test.ts`（輸出在 `tmp/fringe-out/`，tmp 為暫存區，刪了可重跑）

## 發現

1. **邊緣殘色確實存在，可量化**：去背結果有約 5.3 萬個半透明邊緣像素（0 < alpha < 255），平均色 RGB(175, 186, 201)——明顯偏向原背景的藍灰色。@imgly 的 matting 模型只算 alpha、不做 color decontamination，邊緣像素的 RGB 仍「記得」原背景顏色。
2. **明顯程度取決於新背景與殘留色的對比**：
   - 白／淺色背景：看不出來（殘色本來就偏淺）。
   - 深色或飽和背景：4x 放大可見約 1–2px 淡色暈邊；貼圖實際顯示尺寸（≤370×320）下不顯眼。
3. **白描邊完全吸收殘色**：描邊層墊在原圖下方且外擴超過暈邊寬度，半透明邊緣混色的對象變成描邊色，與背景的交界則是實心 alpha，無混色問題。
4. **本次素材是最好去背的情況**（AI 產的乾淨單色底）。真實照片（頭髮絲、雜亂背景、與背景同色衣物）的殘色會更寬更髒，結論 2 的「不顯眼」不能直接外推到照片來源。

## 對「套用背景」功能的建議

1. **預設搭配描邊**：用戶選了背景（尤其深色／飽和色）時，把白描邊預設打開或至少提示。這同時也是 LINE 貼圖的傳統視覺語言。注意 web 版 UI 描邊預設是關的（`web/src/ui/BuildTab.tsx`）。
2. **無描邊路徑做 1px alpha choke**：疊背景前對 alpha 做 1px 侵蝕＋輕微羽化，成本低、能切掉大部分受污染的半透明像素。若用戶輸入以照片為主，建議直接做成疊背景流程的固定步驟。
3. **Defringe（color decontamination）暫不做**：用鄰近不透明像素顏色取代半透明像素 RGB 的做法更講究，但以貼圖顯示尺寸而言屬過度工程；除非未來支援大尺寸輸出再考慮。
4. **管線順序**：去背 → 描邊 → **最後**疊背景做最終合成。疊上背景後整張變不透明 PNG，LINE 規格允許（滿版貼圖本來就存在）。
