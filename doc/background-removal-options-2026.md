# Background-removal options for `sticker-tool`

**Research date:** 2026-08-12
**Scope:** local/open-source models, hosted APIs, and deterministic methods for generated solid-background images and video. Links below are to primary sources (project repositories/model cards, provider documentation, pricing, terms, or papers).

## Decision in brief

For this repository's generated, mostly flat-background sticker artwork, the safest default remains the existing deterministic **outer-edge-connected solid-color key**. It removes pixels that look like the selected background *and* connect to the image boundary, so matching-color regions enclosed by a subject are retained. The existing web contract also has an explicit whole-image mode; that mode intentionally removes matching foreground pixels. See the [current README](../README.md), [architecture](../ARCHITECTURE.md), and the repository's [border-connected removal note](border-connected-background-removal.md).

The strongest shortlist by use case is:

1. **Known-color outer-edge key** for generated solid backgrounds, especially when preserving every glyph, detached decoration, limb, and hair strand matters more than automatic tolerance to a dirty background. Keep the original pixels as a recoverable source, but reconstruct/decontaminate RGB in the final semi-transparent edge band so the keyed background does not remain as a fringe.
2. **Browser-local BiRefNet Lite 512** as a no-upload semantic baseline. The official derived model is an ONNX export for Transformers.js/WebGPU with WASM fallback, but its 512-pixel input is a real fine-detail limitation ([model card](https://huggingface.co/studioludens/birefnet-lite-512), [upstream implementation](https://github.com/ZhengPeng7/BiRefNet)). It is already an experimental adapter in this project.
3. **Prompted SAM 2 plus optional ViTMatte refinement** when a user can mark each intended foreground object and the job contains arbitrary separated lettering, symbols, props, or effects. SAM 2 supplies points/boxes/masks and video memory; ViTMatte refines a user-provided trimap rather than discovering the foreground ([SAM 2](https://github.com/facebookresearch/sam2), [ViTMatte](https://github.com/hustvl/ViTMatte)). This is a Colab/desktop workflow, not a static-browser drop-in.
4. **Background Matting V2 with a clean plate** for fixed-camera video when a clean background frame can be supplied. It is a strong extra-signal method, but the official repository warns that its sample video conversion script is not production real-time and needs separate encode/decode engineering ([official repository](https://github.com/PeterL1n/BackgroundMattingV2)).
5. **withoutBG local/open weights** for private Python/CPU A/B tests, and its Pro API for a deliberately server-backed experiment. This is practical, but the open model is a composite license (Apache code plus DINOv3 terms), not simply “Apache-2.0” ([SDK](https://github.com/withoutbg/withoutbg-python), [open-model license](https://withoutbg.com/open-model/license)).

Hosted remove-background services are useful for quality comparisons, not for the current static web default: they require uploading pixels and an API key. Adding one would require a backend/proxy, cost and privacy disclosures, and an explicit adapter/architecture decision.

## The preservation question

The relevant distinction is not “which semantic model has the best person benchmark?” It is “what additional evidence tells the remover which pixels the creator means to keep?”

| Available evidence | What it can preserve | Main failure/risk | Fit here |
| --- | --- | --- | --- |
| Known background RGB plus outer-edge connectivity | All pixels that are not classified as connected background, including non-person text and detached decorations | Foreground touching the boundary, color spill, or a foreground pixel indistinguishable from background | Best first pass for generated flat backgrounds; deterministic and local ([project contract](border-connected-background-removal.md)) |
| Clean plate/background reference | Background that is not connected to the outer edge; soft boundaries when registration is good | Camera/geometry changes, shadows, and regions never visible in the clean plate | Best extra cue for fixed-camera video ([Background Matting V2](https://github.com/PeterL1n/BackgroundMattingV2)) |
| User point/box/mask prompts plus video state | Explicitly selected separate letters, props, limbs, hair, or effects; propagation across frames | Every disconnected element may need a prompt/correction; output is a segmentation mask, not automatically a perfect alpha matte | Best preservation-oriented interactive route ([SAM 2](https://github.com/facebookresearch/sam2)) |
| Trimap around a selected object | Fine hair/soft edges and semi-transparent boundaries | A trimap is required; it does not decide which objects to keep | Refinement stage after keying or prompting ([ViTMatte](https://github.com/hustvl/ViTMatte)) |
| Zero-prompt semantic foreground mask | Common people/products/animals and some graphics | The model may classify small text, particles, glows, or detached objects as background; masks can flicker frame-to-frame | Candidate baseline only (IMG.LY, BiRefNet, BRIA, remove.bg, Photoroom) |

**Inference (important):** a semantic remover receives pixels and predicts a mask/alpha; it is not given a declarative list saying “keep every glyph, decoration, limb, and hair strand.” Therefore no zero-prompt semantic model can guarantee zero content loss on arbitrary generated art. A benchmark or a model card's “text”/“multiple objects” examples are evidence that such cases occur in its data, not a guarantee for this project's images. The information-theoretic limit is stronger for a solid key: if foreground and background pixels are identical and touching, one image alone contains no fact that identifies the creator's intent. The project should expose a preview and allow no-removal, keying, or manual/prompted correction rather than promise perfect automatic recovery.

## Repository fit and integration boundary

`sticker-tool` is a deterministic Node CLI plus a static React/Vite app. The current five browser modes are none, solid-color keying, browser-local IMG.LY, browser-local BiRefNet, and a user-started temporary Colab mask endpoint ([architecture](../ARCHITECTURE.md), [README](../README.md)). The Colab adapter receives a same-size grayscale mask and applies alpha locally; the local BiRefNet adapter runs sequentially in a worker. Shared `src/core/` must remain platform-neutral. A new provider, model download, prompt UI, or backend should therefore live in a runtime adapter and be preceded by an architecture decision; this note makes no code change.

For video, keep the existing fixed source grid and lazy mask/cache behavior. A per-frame image model is not a temporal model; without explicit propagation or stabilization, thin text and small decorations can appear/disappear or flicker. The repository's current BiRefNet feasibility note records this limitation and recommends crop-first inference and frame inspection ([`doc/birefnet-browser-mobile-feasibility.md`](birefnet-browser-mobile-feasibility.md)).

## Deterministic and background-matting approaches for solid-background video

### 1. Known-color key with an outer-edge rule

When the generator uses a known flat RGB background, keying is the only option in this shortlist that can preserve arbitrary content without asking a model to recognize it. The project implementation compares color distance, flood-fills candidate background from all four edges, and applies a selected hard/soft fringe policy. It retains enclosed same-color regions in the safe mode; the opt-in whole-image mode removes every matching pixel. This behavior is documented in [the current README](../README.md) and [the border-connected design note](border-connected-background-removal.md).

For video, estimate/choose the background using representative frames, then reuse one setting over the fixed source grid and inspect every retained frame. Do not independently choose a semantic mask per frame and assume visual consistency. Preserve the untouched source RGB and mask non-destructively so removed text/decorations can be restored. In the rendered result, however, solve both alpha and foreground color inside a narrow unknown edge band (or inverse-composite against the known background) and apply spill suppression/defringing; changing alpha alone leaves the background color baked into anti-aliased edge pixels. A foreground region that is exactly the background color and touches it remains fundamentally ambiguous (the inference above), so expose no-removal/manual correction for that case.

### 2. Clean-plate matting

[Background Matting V2](https://github.com/PeterL1n/BackgroundMattingV2) explicitly requires an additional captured background image and reports high-resolution matting performance (4K 30 fps/HD 60 fps on an RTX 2080 Ti). Its repository is MIT and includes image/video scripts and Colab notebooks, but it warns that the included video conversion path lacks hardware-accelerated/parallel encoding and decoding and is not itself production real-time. For generated video with a fixed camera and a clean empty-background render, this is the strongest non-semantic candidate to prototype after the color key. It still depends on accurate registration and the foreground/background assumptions; test with the project's text, detached-decoration, hair, and moving-limb fixtures.

### 3. Prompted segmentation followed by matting

Use SAM 2 to mark the objects the creator wants to retain, propagate them across the video, then optionally pass a narrow unknown band to ViTMatte. This adds the missing “what should stay?” signal and is therefore more defensible for arbitrary separated elements than a zero-prompt person model. It is interactive and heavier, and it should remain a user-started Colab/desktop workflow. SAM 3/3.1 is a current open-vocabulary alternative with text/exemplar/point/box/mask prompts and video tracking, but the official repository requires Python 3.12+, PyTorch 2.7+, CUDA 12.6+, gated checkpoints, and a separate custom SAM license; it is not the first integration target ([SAM 3/3.1 repository](https://github.com/facebookresearch/sam3), [installation](https://github.com/facebookresearch/sam3#installation)).

## Recommended next experiment (no code change in this note)

Build one evaluation fixture set containing: (a) black/green/near-solid backgrounds, (b) black hair/clothing on a black background, (c) opaque requested lettering, (d) detached punctuation/hearts/speed lines, (e) translucent glow, and (f) motion across the same source grid. For each option record missing-foreground pixels, false foreground pixels, edge halo, and frame-to-frame mask changes.

Run the following order:

1. Existing `none` and outer-edge key; retain the source as the pixel-preserving control.
2. Current upgraded keyer: evaluate its sampled background-color cluster, foreground/background/unknown trimap, reconstructed/decontaminated edge RGB, and spill suppression before considering a semantic-model replacement.
3. Existing browser IMG.LY and local BiRefNet Lite 512; compare at crop resolution, not after shrinking a whole sheet.
4. Clean-plate Background Matting V2 if a matching empty-background render is available.
5. Prompted SAM 2 plus ViTMatte on the difficult cases only; measure user correction time as well as pixels.
6. withoutBG local, then BRIA/withoutBG Pro/Photoroom/remove.bg/Cutout.Pro as opt-in server A/B tests. Use hosted BRIA for commercial evaluation rather than redistributing the non-commercial RMBG 2.0 weights.

Do not change the deterministic CLI or static web default to a hosted provider. If a new model is adopted, pin the code, weight revision, runtime, checksum, and license notices; document whether it returns a binary mask, soft alpha, or an alpha-plus-foreground reconstruction; and keep a visible preview/manual escape hatch. Successful model inference is diagnostic evidence, not proof that LINE will accept the final package.

## License and operational checklist

- **Code license is not weight license.** IMG.LY is AGPL; BiRefNet/SAM 2/ViTMatte/Background Matting V2 repositories advertise permissive code licenses; BRIA RMBG 2.0 is CC BY-NC; RVM is GPL-3.0; withoutBG combines Apache code with DINOv3 terms. Audit the exact checkpoint and redistribution path before commercial use.
- **Do not put API keys in static JavaScript.** Hosted options require a backend/proxy, rate-limit handling, upload/retention policy, and a user-visible opt-in.
- **Do not turn a semantic score into a preservation promise.** Accept/reject masks using representative fixture evidence and expose `none`, deterministic keying, or correction when a small element is missing.
- **Treat hair and glow as matting, not only segmentation.** A good object mask may still need a trimap/refiner and foreground-color/spill handling.
- **Treat animation as a temporal problem.** Cache a single model session, process sequentially, inspect all source frames, and measure flicker; a still-image API's per-frame outputs are not automatically consistent.
