## 1. 回嘴貼圖製造機

### TL;DR

- **聊天當下打一句話 → 疊到既有角色圖庫上 → 秒出一張一次性回嘴圖 → 傳進 LINE。**
- 不生圖、不打 API：圖庫用 char-gen 已產出的角色圖，疊字用現成的 `overlayText`（`web/src/webpipe/text.ts`），全程瀏覽器本機完成，零成本。
- 形式：web 版新增一個「回嘴」分頁（已有 GitHub Pages 部署、手機破版也修過），手機加到主畫面當 PWA 用。
- 速度是命：從開頁到送出目標 **5 秒內**，否則聊天時機就過了。

### 使用流程（目標體驗）

1. LINE 聊天中產生回嘴需求 → 切到回嘴頁（主畫面圖示）
2. 圖庫網格挑表情（最近用過的排前面，可選 tag：嗆、無奈、得意、裝死…）
3. 打字（預設：大字、白描邊、底部置中——梗圖視覺語言）
4. 點「分享」→ iOS share sheet → LINE → 送出

第 2、3 步可互換；常用句（「好喔」「你說得都對」）可以做成一鍵套用。

### 重用現有資產

| 需求 | 現成件 | 備註 |
|---|---|---|
| 疊字 | `web/src/webpipe/text.ts` `overlayText` | halo 外框兩層畫法，任何底色可讀；支援上傳字型 |
| 角色圖庫 | char-gen skill 既有產出 | 同臉同角色多表情，本來就是為貼圖產的 |
| 部署 | `web/`（Vite + React，GitHub Pages） | 新分頁加進 `App.tsx` 的 `TABS` 即可 |
| 手機可用性 | 已有 mobile-check 腳本 | 這個功能手機是主場景，破版檢查直接沿用 |

### 關鍵設計決策（待定）

1. **圖庫存哪**：建議瀏覽器 IndexedDB——首次把角色圖（單張或 zip）匯入後離線可用，跨次保留；不放 repo（角色圖是個人素材，且 Pages 是公開的）。
2. **出圖路徑**：canvas → blob → `navigator.share({ files })` 直接帶圖進 share sheet（iOS Safari 支援）；fallback 長按複製圖片。不需要走 LINE 貼圖規格——這是「傳圖片」，不是上架貼圖，尺寸自由。
3. **多行字**：現有 `overlayText` 單行置中。回嘴常常超過一行，需要補「手動換行 + 自動縮字到不出血」；這是唯一要寫的新邏輯，其餘都是組裝。
4. **挑圖速度**：tag 分類 + 最近使用排序。圖庫超過 ~20 張後，挑圖會變成流程瓶頸，這兩個排序就是為了守住 5 秒目標。

### MVP 切法

- **v0**：新分頁＋匯入圖片進 IndexedDB＋點圖打字（單行）＋share/複製。半天內可完成，先驗證「真的會在聊天時打開它」。
- **v1**：多行/自動縮字、tag、最近使用、常用句。
- **不做**：生圖（破壞零成本前提）、上架打包（BuildTab 已有）、Android 以外不另做 app——PWA 就好。

### 風險／未知

- `navigator.share` 帶檔案在 iOS Safari 的實際體驗（是否每次都列出 LINE）需實測；最壞 fallback 是長按複製，多一步但可接受。
- 一次性梗圖傳進 LINE 會被壓縮，透明背景可能被墊白——疊個底色或乾脆輸出不透明圖即可，不影響用途。
- 真正的成敗不在技術，在「聊天當下會不會想起它」。v0 故意做小，先讓它上手機主畫面待一週看使用次數。

## 2. 梗圖管家

**痛點**：存下來的梗圖散在相簿裡，要用的時候永遠找不到——和回嘴貼圖同一個「聊天當下」場景。

- 流程：看到好梗圖 → share extension 一鍵「存進梗庫」→ 背景用現成 gemini OCR 讀圖上文字當索引 → 聊天時搜關鍵字秒中。
- 重用：media-dler-ios 的 share extension 經驗、gemini OCR 快速工具。
- 形式待定：iOS 小 app（share extension 是關鍵入口）＋本機 SQLite/檔案庫；或存進同步資料夾、搜尋介面走 web。
- OCR 之外可補一層便宜模型下情境 tag（嗆人／無奈／慶祝），每張一次性成本趨近零。
- 與回嘴貼圖互補：一個用現成梗圖，一個現做；搜尋介面甚至可以共用同一個頁。

## 3. 語音梗 soundboard

**痛點／樂趣**：語音回嘴比貼圖更賤。「你完蛋了」「就這？」三秒金句當語音訊息丟出去。

- 流程：media-dler 抓片 → ffmpeg 切三秒段 → 存進音效板（標題＋tag）→ 聊天時點一下 → share 成音檔丟進 LINE。
- 重用：media-dler（抓片＋已掛 audio2text，可自動給切點候選字幕）、ffmpeg。
- 未知：LINE 收到音檔的播放體驗（非原生語音訊息泡泡）需實測；最壞當一般檔案傳，樂趣略減。
- 等於梗圖管家的聲音版，「管家＋board」的庫存結構可以共用設計。

## 4. 貼圖試衣間

**痛點**：上架前看效果現在只能傳給自己。補貼圖產線缺的最後一塊 QA。

- web 加「聊天室預覽」分頁：把做好的貼圖（或整包 zip）丟進仿 LINE 聊天 UI——深淺色主題、實際顯示尺寸、單發／連發、配上對話泡泡情境。
- 動態 APNG 直接在預覽裡循環播放（web 已有 APNG 管線）。
- 純前端、零成本、半天工作量；偏「有用」多於好玩，但使用頻率綁著每一包貼圖的製作循環。

## 5. 金句卡產生器

**素材**：whisper 逐字稿庫裡躺著大量理財金句。

- 流程：選一句（手動挑，或便宜模型從整篇逐字稿撈金句候選）→ 套排版模板（字級層次、引號、出處小字）→ 出圖分享。
- 與回嘴貼圖共用疊字引擎，差別只是模板氣質——一個用來嗆人，一個用來裝深度。
- 進階玩法：用現成 APNG 編碼器做「打字機效果」動態金句卡，分享出去辨識度高。
- 成本：純本機零成本；金句自動撈取走 openrouter 便宜模型，一篇逐字稿不到一塊錢。

## 6. 動圖回嘴（GIF 字幕機）

**定位**：回嘴貼圖 v2——會動的嗆人圖殺傷力翻倍。

- 流程：從梗庫挑 reaction GIF →（拆格）→ 每格疊字 → 重新編碼 → share 丟出去。
- 重用：gif-frames 拆格、APNG/upng 編碼管線、`overlayText`——三個既有零件接起來，沒有新引擎。
- 與回嘴貼圖（#1）共用分頁與圖庫結構：靜圖走 PNG 路徑、動圖走 GIF/APNG 路徑，UI 不變。
- 與梗圖管家（#2）銜接：管家存的動圖就是這裡的素材庫。
- 注意：LINE 聊天傳 GIF 才會自動播放（APNG 當一般圖片），輸出格式以 GIF 優先；逐格疊字後重編碼的檔案大小需留意（縮格數/減色都有現成手段）。

## 7. 字幕燒錄片段機

**痛點**：分享影片片段給群組，大家都靜音滑手機——沒字幕就沒人看。

- 流程：URL＋起迄時間 → media-dler 抓片 → ffmpeg 切段 → media-dler 已掛的 audio2text 產字幕 → ffmpeg 燒進畫面 → 丟群組。
- 重用：所有零件都在 media-dler 身上，只差一條膠水管線；唯一新邏輯是字幕樣式（字級、描邊、位置——可參考疊字引擎的梗圖視覺語言）。
- 定位：歸在 media-dler 的延伸功能也行，先記在這裡。同場加映被淘汰的鄰居點子（語音輸入打磨、剪貼簿轉換、私人 podcast feed、語音訊息轉文字）多半是 media-dler 既有能力的包裝，不另立項。

## 8. 雲端發票自動記帳

**機制有趣、實用性存疑**（記錄時的評價）：記帳 app 死於要手動記，但台灣的手機載具讓發票資料在結帳當下自動進財政部系統——**零自律成本的記帳**，工具自己動。

- 流程：定期拉載具消費明細（財政部電子發票 API）→ 自動分類 → 月報表。
- 與現有工具完全無關，亦無重用件；價值取決於「看到自己消費數字」的需求強度，目前評估不高，先掛著。
- 若做，分類可走 openrouter 便宜模型，一個月明細一次呼叫，成本趨近零。

## 9. AI 鐵口直斷

**純娛樂擔當**：聚會時拍張手相／面相照 → 便宜視覺模型用江湖術士口吻胡謅一段命理 → 全桌搶著拍。

- 資訊價值零、社交價值滿點；fun tools 的「fun」字面擔當。
- 形式：極簡網頁（拍照／選照片 → 出結果卡），一次視覺呼叫幾毛錢，半天可完成。
- 口吻是靈魂：prompt 要寫足江湖味（「印堂發亮，近期有貴人」），結果做成可分享的圖卡（又能借 `overlayText` 排版，但非必要）。
- 可延伸：塔羅、籤詩、紫微等模式切換，本質都是同一個殼。
