# char-gen：角色一致性產圖

## 核心信念（其他都在服務它們）

1. **角色一致性來自「餵回同一張真實參考圖」，不是來自文字描述。** 文字一定會漂移；只要每次都把同一張圖透過 `codex exec -i` 餵進去，模型就有視覺基準可對齊。
2. **動作自然度來自「你逐格寫死的分鏡」，不是來自模型的內插。** 模型不是動畫引擎，叫它「相鄰格差異小、串起來流暢」只會得到跳格與死臉。你當動畫師、它當畫師。

所以你（agent）的工作是：**每次餵對同一張圖、每次只改一件事、把每一格寫到沒有想像空間。** 文字只負責釘住參考圖裡最難「猜錯」的獨特特徵，以及每一格的姿勢與表情。

```
真實照片 ──[建立]──> 參照圖(master)  ──[變化]──> 貼圖/影格/情境圖
                         │  (這張是之後所有圖的唯一基準)        │
                         └──────────[發現漂移就點名修正]────────┘
```

## 流程

1. **判斷角色來源**：使用者給的是「真實照片」還是「已經是參照圖」？
   - 真實照片 + 只想要單張 → 可直接用照片產。
   - 真實照片 + 要做貼圖/影格（多張） → **強烈建議先產一張參照圖**再以它為基準，否則多張之間會各自漂移。先告訴使用者這個取捨，再決定。
   - 已有參照圖 → 直接進「變化」。
2. **看圖、抽 signature features**：用 Read 看一眼來源圖。找出**2–4 個最獨特、最難被模型猜錯的特徵**（痣、異色瞳、奶嘴、特定印花、某種髮型）。這些是抗漂移的主力——普通的「黑短髮男孩」會漂，「嘴含橘色奶嘴＋頭頂豎髮＋恐龍 T 恤」不會。寧可多抓幾個。
3. **組提示詞**：用 `[REFERENCE] + [LOCK] + [TASK] + [VARIATION] + [NEGATIVE]` 五段骨架。LOCK 與 NEGATIVE 幾乎固定（鎖住身分），每次只動 TASK（這次要產什麼版面）與 VARIATION（這次改哪一件事）。版面（單張／組圖／影格）由使用者要求的語意決定，別硬套格數。完整的五段骨架、Character Bible 欄位、與 A/B/C 三段模板，見 `references/method.md`——**第一次做或不確定怎麼填時務必去讀它**。
   - **連續影格／動作組圖：分鏡逐格寫死，列給使用者確認再跑。** 模型不是動畫引擎——「相鄰格差異小、串起來流暢」這種抽象指令它無從執行，只會自由發揮成跳格＋死臉。動作設計是你的工作，模型只負責照著畫：每格一行「姿勢＋表情」，用 method.md 第 5 節的動畫原則（緩入緩出、預備動作、跟隨、表情弧線）設計，預設 8 格起步。
   - **動作來源是現成動畫（GIF／影片）時：拆格拼「動作對位圖」當第二張 `-i`。** 來源拆格、等距挑 N 格、拼成與輸出同構的網格圖（白底、標格號），與 master 一起餵入。文字用極簡配方：**任務規格＋一句「產出的圖必須維持第一張參考圖的臉部辨識度」**——六組 ablation 中性價比最高，畫風與姿勢對位兼得（`dance20_v6`）。要加負向畫風鎖（一排「不可」）就必須同時用正向句撐回第二張的姿勢權威（「格N 姿勢＝對位圖格N、動作幅度照搬不要收斂」），否則姿勢忠實度陪葬（ablation `dance20_v4`）。三個實測風險：(1) 極簡配方沒有 NEGATIVE 點名，對位圖的服飾道具偶爾滲漏髒格——產後逐格檢查，中招點名該格重跑、**別讓 codex 自由發揮局部修補**（實測把人物嘴部擦壞）；(2) 餵兩張參考圖時模型常走「畫綠幕再自行去背」彎路（單參考圖同措辭則直出透明），產後透明驗證不可省；(3) 多排 sheet 越下排人物畫越小（實測第四排比第一排小 20%），normalize 時按排補償。做法細節見 method.md 第 5 節末。
4. **呼叫 codex**（指令見下），輸出到使用者指定路徑；未指定時放專案慣例目錄（此專案為 `spike/`）。
5. **驗證（三道，缺一不可）**。注意：用 Read 直接看透明 PNG 不可靠——透明區會渲染成黑色或殘留原 RGB，**先用 sharp `flatten` 合成到灰底（#f0f0f0）再看**。
   - **透明**：合成灰底後檢查——背景是真 alpha，而不是畫出來的「棋盤格／純色假透明」（實測 `montage.png` 曾畫假棋盤格充當透明）？多格圖的格間 gutter 與**每格的底**也都透明（實測曾每格畫白色卡片底）？角色身上原本就白／亮的部位（白衣、眼白）沒被去背流程挖洞（鍵控與顏色 flood fill 都有這個風險）？殘留白底要救時，**別用顏色閾值去白**（會從白衣過曝交界滲入挖洞）——逐格 flatten 成白底照片再用 @imgly 語意去背（白底單人像是它的甜蜜點，白衣保得住）；主體貼近格緣時 imgly 會給**半透明鬼影**（實測高舉的手臂變半透明），先加白邊 padding 再去背、裁回即解。鬼影可客觀偵測：掃各格 alpha 40–220 佔比，正常邊緣帶約 1–2%，≥3% 就該放大看。
   - **一致性**：逐一對照 signature features，有漂移就點名。
   - **自然度**：逐格掃詭異格（眼神上吊／斜視、手指數量與形狀、肢體錯位）、動作是否照分鏡走、表情有沒有跟上動作、各格主體大小位置是否對齊；**人物有沒有越過格線**——高密度網格（5×4 以上）模型常把格高用爆（實測 256px 格畫出 273px 人物、上排的腳掉進下排格頂），用連通塊或逐欄投影檢查，中招就跑 `scripts/normalize-sheet.mjs <in> <out> <cols>x<rows>`（連通塊重排成嚴格等分：全域縮放＋排基線對齊、保留跳起格離地量）再切格；**越下排人物越小**（多排 sheet 的系統性傾向，實測第四排比第一排小 20%）就加 `--equalize-rows`（每排高度中位數補償到最高排，排內蹲跳差異保留）；影格類先串成動畫動起來看（sticker-tool `anim --sheet --grid`，**輸出檔名別與 sheet 同名，會原地覆寫輸入**）再給使用者。
   任一道有問題，都用 `references/method.md` 模板 C 點名該處修正再跑，不要重頭描述。

## codex 指令

把提示詞寫進暫存檔再帶入，避免 shell 引號地獄：

```bash
codex exec \
  -i <參考圖絕對路徑> \
  -s workspace-write \
  -c sandbox_workspace_write.network_access=true \
  -C <輸出目錄絕對路徑> \
  --skip-git-repo-check \
  "$(cat /tmp/char-gen-prompt.txt)"
```

要點：
- `-i` 是整個 skill 的支點。做貼圖/影格/情境圖時，這裡一定餵**參照圖（master）**，不是原始照片。
- 提示詞**結尾要明寫檔名與最小解析度**（例：`存成當前工作目錄下的 char_sheet.png，PNG，至少 1536×1024`），codex 才知道存哪、不會給你迷你縮圖。
- codex 第一次 image_gen 偶爾回 server error，它通常會自動重試；真的連續失敗就重跑一次指令（實測曾連錯 7 次後恢復，等 1–2 分鐘再重跑值得）。
- **提示詞要加一段「執行規則」防呆**：明寫「只能用內建 image_gen；server error 就等幾秒重試（最多 5 次）；絕對不要改用程式化繪製（PIL/SVG/canvas）；持續失敗就直接回報失敗」。實測 image_gen 連錯兩次後 codex 會自作主張改用 PIL 把設定圖「畫」出來——監看它的輸出，看到走偏立刻砍掉重跑。
- **codex 自稱完成≠檔案在工作目錄**：image_gen 預設存到 `~/.codex/generated_images/<session-id>/`，codex 可能漏掉「搬進 workspace」那步（實測中招）。產完先 `ls` 驗證輸出路徑，不在就去 generated_images 按 session id 撈出來自己 cp。
- 多張產完後若要切格/去背/打包成 LINE 上架包，那是本專案 `sticker-tool` 的確定性流程，不歸這個 skill；這個 skill 只負責「畫出一致的角色」。

## 輸出硬規則（每次都做）

- **連續影格＝一張「多格網格圖」**：codex 產**單一 PNG**，把 N 格排成網格（**預設 4×2＝8 格起步**——格數愈多每格愈小、臉愈容易崩；驗證過弧線再考慮 4×3 / 4×4），reading order 左→右、上→下，**不是多張獨立檔**。之後交 sticker-tool `anim --sheet --grid` 切格＋穩定化。
- **網格要留乾淨間隙＋構圖錨點**：格間留明顯**透明**間隙（gutter）、每格主體完整置中留 margin、手腳/道具**不可越過格線**——否則等分切會切到手、或把隔壁格的手夾進來。「各格大小一致」太抽象，要給可對齊的錨：同一鏡頭距離與取景、頭部中心落在每格同一相對位置、人物佔格高固定比例（約 75–80%，舉手仍不出格）。
- **一律全張透明背景，直接要求**：所有產出都請 codex 直接出**透明背景 PNG**（alpha=0），且要講到這個程度：「**全張透明——唯一不透明的像素是角色本身**；多格圖的格間 gutter 與每格底也都是透明，不要每格畫一張白色卡片底」（實測 `cheer8_v2` 曾每格畫白卡底，切出動畫後白塊邊緣跳動很醜）。image_gen 做得到（實測 `cheer_16.png` 直出真 alpha）；**別引導它走「畫純色底再去背」的彎路**（實測它會自選鍵控色甚至 key 錯，把白 T 恤挖洞）。需要背景一律後期合成，別讓 codex 畫場景背景。
- **prompt 嵌進 PNG**：每張產完後，把這次的提示詞寫進 `iTXt[prompt]`（PNG 標準文字 chunk，非 EXIF）：
  ```bash
  node <此skill目錄>/scripts/png-prompt.mjs embed <產出.png> /tmp/char-gen-prompt.txt
  ```
- **每一格都要寫表情**：VARIATION 逐格帶表情、隨動作強度遞增（峰值最強）——哪格留空，哪格就是中性死臉。master 是多視角合成圖時，TASK 指明取哪個視角＋表情當基準。
- **寫實風×誇張動作＝恐怖谷，要主動提醒**：寫實照片風的角色做貼圖式誇張動作（比心、飛吻），成品天生容易詭異。用途是貼圖時主動建議使用者轉插畫風 master（見 method.md 第 5 節）；堅持寫實就把動作收斂到真人做得出來的幅度。

## 抗漂移要點

- **每次都用同一張 master 當 `-i`。** 換參考圖＝換基準，一致性立刻崩——這是一致性的根本來源。
- **一次只改一件事。** 同時改場景、服裝、鏡頭，模型會趁亂把臉也改掉。鎖住其餘、只動一個變數。
- **大改方向另起新 master。** 換畫風／年齡／性別這種根本改變，別硬凹同一張，先重做一張新 master 再分支。
