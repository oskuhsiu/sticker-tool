# char-gen 方法論：把角色凍結、把分鏡寫死，只改一件事

這份是 SKILL.md 的延伸細節。SKILL.md 講「為什麼」與流程；這裡給你「實際怎麼填字」。
方法論源自 `plan/character-consistency-guide.md`（Codex Images 維持角色一致性指南），這裡萃取成可攜、可直接套用的版本。

## 1. Character Bible —— 把角色凍結

第一次拿到角色（真實照片或設定）時，寫下這份「角色聖經」。重點不是寫好看，而是**把模型會自由發揮的每個欄位都釘死**，尤其是 signature features。

```text
Name: [角色名]
Sex / Age: [男童 / 約 4 歲]
Face: [臉型、眼型、膚色、五官比例：圓臉、單眼皮、黑眼睛、鼻樑小巧、白皙紅潤]
Hair: [顏色、長度、造型：黑色短髮、頭頂髮絲明顯往上豎起]
Body: [身形、頭身比：幼兒身形、約 4 頭身]
Signature features（一定要出現，2–4 個最獨特的）: [嘴含橘色奶嘴、胸前一排藍色小恐龍印花]
Outfit（預設服裝）: [白色短袖圓領 T 恤]
Art style: [與上傳照片相同的寫實兒童攝影風格，自然柔光，不卡通化、不動漫化]
```

**Signature features 是抗漂移的主力。** 挑選原則：愈獨特、愈難「猜錯」愈好。
- 弱（會漂）：黑長髮、戴眼鏡、穿白衣
- 強（抗漂）：左眼下淚痣、異色瞳（左藍右金）、銀色耳骨環、嘴含橘色奶嘴、胸前特定恐龍印花

寧多勿少——模型漂移的本質是「在你沒講清楚的地方自由發揮」，特徵給愈滿，它能亂改的空間愈小。

## 2. 五段提示詞骨架 —— 每次出圖的填法

任何要求都套這個骨架。**LOCK 和 NEGATIVE 幾乎固定不動**（它們是鎖住身分的鷹架），每次只動 TASK 和 VARIATION。

```text
[REFERENCE] 使用我上傳的角色參照圖（codex 由 -i 帶入）為唯一身分基準。

[LOCK — 不可改動]
臉部、五官比例、髮型髮色、體型、年齡感、畫風，以及所有 signature features
（[逐一列出，例：橘色奶嘴、恐龍印花 T 恤]）必須與參考圖完全一致。

[TASK — 這次要產什麼]
[版面 + 背景 + 檔名 + 解析度。例：單張方形；或 4×2 多格組圖；或「一張 4×2 網格＝8 連續影格」。背景按優先序：真透明 RGBA（alpha=0x00，整張唯一有像素的只有主體＋互動／手持物件）≫ 退路純綠幕 #00FF00 且不自行去背 ≫ 絕不白底／棋盤格假透明（細節見 SKILL.md〈輸出硬規則〉）；連續影格務必是「單張多格網格圖」、非多檔]

[VARIATION — 這次只改這裡]
[場景／姿勢／鏡頭／表情／服裝，只放真正要變的那一兩件事；連續影格／動作組圖則放第 5 節的逐格分鏡清單]

[NEGATIVE — 避免]
不要改臉型、不要改髮長、不要換年齡、不要漂移畫風、不要新增或刪除 signature features、
不要加文字浮水印、不要畫背景（背景一律留透明）。
```

> 小技巧：把 LOCK 與 NEGATIVE 當成固定片語存著，每次只重寫 TASK 與 VARIATION，能大幅降低手動描述造成的漂移。

## 3. 模板 A：建立參照圖（master）—— 只做一次

第一次拿到真實照片時用這個。`-i` 帶**真實照片**。把 LOCK 換成完整的 Character Bible（上面第 1 節）。產出的這張 master，是之後所有圖的唯一基準。

TASK 範例（角色設定圖）：
```text
[TASK]
單一影像的角色設定圖（character design sheet），純白背景：
- 上排 turnaround：正面、3/4 側面、正側面、背面 四視角全身站姿。
- 下排表情表：neutral、happy、surprised、giggle、sleepy、pout 六格頭像特寫。
所有視角與表情之間，臉型／五官比例／髮型／signature features 維持完全一致。
存成當前工作目錄下的 char_sheet.png，PNG，純白背景，至少 1536×1024。
```

挑出最滿意的一張當 master。之後就不再回去用原始照片了。

## 4. 模板 B：變化（每次出圖固定貼，只改 VARIATION）

`-i` 帶**模式 A 的參照圖**。LOCK／NEGATIVE 照抄不動，只改 TASK 的版面與 VARIATION 的內容。

貼圖組範例（注意：**每格都帶表情**，只寫動作會得到一排中性死臉）：
```text
[TASK] 一張 4×2 多格組圖，背景按優先序：**真透明 RGBA PNG（alpha=0x00，整張唯一有像素的只有主體＋手持／互動物件，格間與每格底都是 0x00）≫ 退路純綠幕 #00FF00、不自行去背 ≫ 絕不白底／棋盤格假透明**，每格一個角色、**格間留明顯空隙、主體完整置中留 margin 不越格線、各格主體大小一致**，格與格之間角色完全一致。存成 stickers.png，每格 ≥320px。
[VARIATION] 1.揮手（開心燦笑） 2.比讚（得意瞇眼笑） 3.哭哭（嘴角下垂、淚珠） 4.生氣（鼓臉皺眉） 5.雙手比愛心（甜笑臉紅） 6.睡覺（閉眼安詳、頭歪枕手） 7.加油握拳（振奮張嘴笑） 8.OK 手勢（眨單眼）
```

**master 是多視角／多表情合成圖時**，在 TASK 指明這次取哪個視角＋哪個表情當基準（如「正面、腰部以上、用開心表情」），否則 codex 不知道對齊哪個。

**連續影格／動作組圖：不要把動作設計丟給模型。** 到第 5 節用「分鏡逐格寫死」的方法填 VARIATION——這是產出自然與否的關鍵，也是本 skill 最容易失敗的地方。

單張情境圖範例：
```text
[TASK] 單張，方形，存成 scene.png，至少 1024×1024。
[VARIATION] 穿太空衣站在月球上，地球在背景，廣角。
```

## 5. 分鏡逐格寫死 —— 自然度與協調感的來源

**為什麼「叫模型自己平滑遞增」一定失敗**：image_gen 不是動畫引擎，它畫一張 16 格網格時是一次畫 16 張「獨立的圖」，不會真的內插。「相鄰格差異極小、串起來流暢」這種抽象指令它無從執行，只能自由發揮——結果就是表情亂跳、手忽高忽低、串起來像壞掉的定格動畫。**動作設計是你（agent）的工作：你當動畫師，模型只當畫師。** 把每一格的姿勢與表情寫到「第 7 格該長怎樣」毫無想像空間，自然度才有保障。

### 怎麼設計分鏡（先弧線、後逐格）

1. **挑一個小動作**，定關鍵姿勢：起點 → 峰值 → 終點（循環動畫終點＝起點）。8～16 格只播 1～2 秒，塞兩個以上動作必跳格。
2. **用動畫原則把中間格填出來**（這些就是「自然」的具體成分）：
   - **緩入緩出**：動作端點附近相鄰格位置差小、中段位置差大。等距均分看起來像機器人。
   - **預備動作**：大動作前先小幅反向（揮拳上頂前，拳頭先微沉一格；跳起前先微蹲）。沒有預備，動作就沒有重量。
   - **跟隨**：主體到位停住後，頭髮、衣襬、配件再多晃半格才停。
   - **表情弧線**：表情強度跟著動作強度走——漸開 → 峰值最強 → 收尾回落。**每一格都寫表情**，留空那格就是中性死臉。
3. **逐格寫成清單**放進 VARIATION，每格一行：`格N：〔姿勢〕，〔表情〕`。每格是靜態快照，不寫「快速」「慢慢」這種速度詞——快慢由相鄰格的位置差大小表現。

### 逐格範例（揮手 8 格循環）

```text
[VARIATION] 動作主題＝揮手打招呼，8 格循環，每格明確如下：
格1：雙手自然垂放身側，閉嘴微笑。
格2：右手微離大腿、肩稍沉（預備），微笑。
格3：右手抬至胸口高度，笑容張開。
格4：右手抬至耳邊、掌心朝前，開心燦笑（表情峰值）。
格5：手掌向外側小幅擺、頭微歪向同側，維持燦笑。
格6：手掌擺回內側，維持燦笑。
格7：手落回胸口高度，笑容略收。
格8：手回到身側、肩放鬆，閉嘴微笑（與格1幾乎相同，循環順接）。
```
（格2→3→4 位置差由小變大＝加速，格7→8 收小＝減速；表情 3 格漸開、峰值在動作頂點。）

### 構圖錨點（協調感來自可對齊的錨，不是「大小一致」四個字）

寫進 LOCK，給模型能對齊的具體基準：
- 同一鏡頭距離、同一取景（如一律腰部以上）、同一光源方向；
- 頭部中心落在每格同一相對位置，頭頂留白比例固定；
- 人物佔格高固定比例（約 75–80%，預留舉手仍不出格的空間）。

### 格數怎麼選

**預設 8 格（4×2）起步。** 格數翻倍＝每格畫布減半、臉部細節變糊變崩、模型分給單格的注意力被稀釋——12 格以上臉部崩壞機率明顯上升。先用 8 格把動作弧線驗證對了，確定需要更滑再上 12／16，並接受臉部細節折損。

### 動作來源是現成 GIF／影片：拼「動作對位圖」餵第二張 `-i`

使用者拿一個現成動畫（GIF、影片）說「跳這些動作」時，別把它翻譯成純文字分鏡——你的轉述會丟失重心、朝向、抬腿幅度這些文字很難寫準的東西。改用對位圖：

1. **拆格**：sharp `{ animated: true }` 讀 metadata 取 pages，逐 page 抽出（`sharp(src, { page: i })`），nearest 放大保留輪廓。
2. **挑 N 格**：來源格數超過目標就等距取樣（如 39 格→20 格取 1,3,5,…），取完目視動作弧線是否完整，關鍵格（轉身、跳起峰值）被跳過就手動換進來。**播放時長要按取樣比例補償**：取了 1/2 的格，每格時長＝原 delay × 2（39 格×120ms 的舞取 20 格 → 240ms/格），照搬慣用的 100ms 等於把動作快轉 2.4 倍（實測踩過）。
3. **拼對位圖**：拼成與輸出**同構**的網格（輸出 5×4 就拼 5×4）、白底、格間留隙——對位靠 reading order 位置：「輸出格N 姿勢＝對位圖格N」（用 `gif-frames` skill 一鍵產；它**預設不標號**，避免編號被 codex 誤畫進輸出格，要除錯比對才開 `--label`）。
4. **雙 `-i` 餵入**：master 在前、對位圖在後。
5. **文字用極簡配方**：任務規格（按第二張的 N 格動作分解、版面同構、透明、檔名與解析度）＋一句「**產出的圖必須維持第一張參考圖的臉部辨識度**」。就這兩句——實測這是性價比最高的配方（見下表）。表情規則是可選加料：對位圖的表情不適用時（如含奶嘴角色不能齜牙），文字改寫成強度對應（「幅度小=微笑、峰值=閉眼燦笑」）。

六組 ablation（同一舞蹈 GIF、同一寫實 master）的結論：

| 文字配方 | 畫風 | 姿勢對位 |
|---|---|---|
| 純文字分鏡（無對位圖） | ✓ | ✗ 站樁擺手 |
| 任務規格一句（零鎖） | ✗ 被平均成卡通 | ✓ 近 1:1 |
| ＋負向畫風鎖（一排「不可」） | ✓ | ✗ 掉回保守 |
| ＋負向畫風鎖＋正向姿勢段 | ✓ | ✓ |
| **任務規格＋臉部辨識度一句** | ✓ | ✓（字最少） |

機制教訓（想加料時要知道）：「維持第一張的臉部辨識度」一句就能把整體外觀權威（畫風、服裝、質感）判給第一張，且因為沒壓制第二張、姿勢權威不受傷。反之負向抑制是粗粒度的——對第二張下一排「不可」會壓掉風格滲透但姿勢忠實度陪葬，補救得加正向句撐回來（「格N 姿勢、朝向、重心、抬哪隻腳＝對位圖格N；動作幅度照搬、不要收斂成保守站姿」——寫實 master 有先驗拉力，會把誇張舞步收斂回照片常見姿態，「不要收斂」是關鍵句）。

極簡配方的代價：沒有 NEGATIVE 點名，對位圖角色的服飾道具偶爾滲漏（實測金色服飾片滲進一格；codex 自行局部修補五輪反而把人物嘴部擦掉）——產後逐格檢查滲漏不可省，中招用模板 C 點名該格重跑，**別讓 codex 自由發揮局部修補**。
另：問過 codex 自述，image_gen 對姿勢參考的有效排序是「彩色人形小人 > OpenPose 骨架 > 純黑剪影」——它不是 ControlNet，沒有結構化姿勢條件，「人形化、語意明確」的參考最可靠；OpenPose 彩色骨架它只能看懂大姿勢與左右編碼、不保證逐點對齊。與實測吻合（彩色小人對位圖的姿勢忠實度確實高），所以對位圖直接用人形小人，不必特製骨架。

風險與省不掉的驗證：對位圖外觀滲漏（見上）；雙參考圖時模型較容易**自行去背**挖洞——背景照 SKILL.md〈輸出硬規則〉的「真透明 ≫ 綠幕＋不自行去背」優先序寫（綠幕當退路 OK，自己 key 才是病灶）；產後透明三道驗證照跑，殘留就按 SKILL.md 驗證節救。

### 寫實風 × 誇張動作 ＝ 恐怖谷（要主動提醒使用者）

寫實照片風格的角色做貼圖式誇張動作（比心、飛吻、誇張大笑），表情肌肉與動作幅度是真人不會有的，成品天生容易「說不上來的詭異」——這不是 prompt 能完全修掉的。若用途是貼圖，主動建議使用者：先轉一張插畫／卡通風的新 master（屬「大改方向另起新 master」），插畫風對誇張動作的容錯率高得多。使用者堅持寫實就把動作幅度收斂到真人做得出來的範圍。

## 6. 模板 C：修正（角色跑掉、或畫面詭異時）

某張圖出問題時，**不要重頭描述、不要砍掉重練**。點名那一處偏差，叫它回到參考圖（或改成自然的樣子），其餘維持上一張。身分漂移和畫面詭異都用這招：

```text
[REFERENCE] 以我上傳的角色參照圖為唯一基準。
上一張出現偏差，請只修正以下幾點，其餘構圖、姿勢、背景維持上一張不變：
- [臉變圓了 → 回到原本臉型]
- [漏掉奶嘴 → 補回橘色奶嘴]
- [第 7 格眼神詭異（眼球上吊）→ 改為看向鏡頭的開心眼神]
- [第 12 格左手手指形狀錯誤 → 修正為自然握拳]
- [第 3 格人物明顯比其他格大 → 縮回與其他格一致的大小與位置]
```

## 7. 版面怎麼選

由使用者要求的語意決定，別硬套格數：
- 「參照圖／設定圖」→ 單張，turnaround + 表情表（模板 A）。
- 「一組貼圖」→ 單張多格組圖（如 4×2），之後由 sticker-tool 切格。
- 「連續影格／動畫／加油序列」→ **單張多格網格圖**（預設 8 格＝4×2 起步，見第 5 節格數取捨；需要更滑才上 4×3 / 4×4 / 6×4），背景按〈輸出硬規則〉優先序（真透明 0x00 ≫ 綠幕退路不自行去背 ≫ 絕不白底／棋盤格）、**格間留明顯空隙、主體留 margin 不越格線**，VARIATION 用第 5 節逐格寫死，之後由 sticker-tool `anim --sheet --grid` 切格＋穩定化。**不是多張獨立檔。**
- 「讓他在某場景做某事」→ 單張情境圖。

## 限制（誠實的期待）

即使照做，仍可能有臉型微變、髮長改變、衣服細節跑掉，換畫風／年齡／性別／種族時尤其明顯。正常情況下這套流程能達到約 80–95% 的角色一致性，遠高於只靠文字提示。
